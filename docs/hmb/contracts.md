## API contract (JSON)
Error {error:string, fields?:Record<string,string>}, normal success {ok:true,...}. Same-origin mutations, JSON only, server validation, opaque IDs. All private responses no-store.
POST /api/applications {idempotencyKey,name,contactMethod:'email'|'phone',contact,offer,experience:'beginner'|'active'|'experienced',difficulty,outcome,format?:'online'|'in_person'|'either',consent:true,marketing?:boolean,website?:string} => {ok:true,reference}. Retried key cannot reveal stored data. Receipt reference passed using sessionStorage only, no PII in URL.
GET /api/auth => {user:null|{id,name,email,role,active}}. POST /api/auth {email,password} => {ok:true,user}; DELETE logs out. No public signup. Seed CLI provisions accounts with hashed passwords.
GET /api/entries => {entries:Entry[]}; POST {instrument,context:'practice'|'live',plan,reasoning,risk,execution?,reflection?,nextAction?} => {entry}. GET/PATCH /api/entries/[id]; PATCH {action:'save'|'submit'|'review'|'acknowledge'|'follow_up',version,...fields,observation?,exercise?,nextAction?}. Entry {id,ownerId,ownerName?,instrument,context,plan,reasoning,risk,execution,reflection,nextAction,status,version,createdAt,updatedAt,feedback?:{observation,exercise,createdAt},history?:unknown[]}. Own member access; assigned-coach access; admin explicitly privileged. Save only draft; submitted immutable. review submitted/in_review -> feedback_ready; acknowledge -> acknowledged; follow_up -> follow_up. GET /api/member/export; POST /api/member/deletion-request {reason?}.
GET /api/admin/applications => {applications:[{id,reference,name,contactMethod,contact,offer,experience,difficulty,outcome,status,assignedTo,notes,createdAt,updatedAt,history}]}; PATCH /api/admin/applications/[id] {status?,notes?,assignedTo?}. Status submitted/under_review/information_requested/accepted/waitlisted/declined/closed with valid transitions. Admin/reviewer only (reviewer assigned records only).
GET /api/admin/users => {users:[{id,name,email,role,active,coachId}]}; PATCH /api/admin/users/[id] {coachId?,active?,role?}, admin only.
GET /api/content?type=article|program|event public published only => {items:Content[]}; GET /api/admin/content all editor/admin => {items}; POST /api/admin/content {type,slug,title,summary,body,status:'draft'|'in_review'|'published'|'archived'}; PATCH /api/admin/content/[id] same. Content {id,type,slug,title,summary,body,status,createdAt,updatedAt}. Body plain text; no untrusted HTML. Public pages can use server getPublishedContent(type,slug?) exported src/lib/db.ts. API same models. Provide sample editorial content labelled as educational draft or editorial exercises; publication guarded.
POST /api/analytics {event,properties} stores aggregate controlled allowlist only, no user identity or text. Events story_section_view,path_selected,offer_view,journal_demo_open,application_start,application_submit_success,application_qualified,onboarding_complete,first_journal_submitted,review_cycle_complete. GET /api/health.

## Authority
Member own entries only. Coach assigned active members only. Editor editorial only. Reviewer assigned applications only. Admin management/audited access. Suspended users denied, sessions expire; secure httpOnly cookie, hashed token at rest. Membership entitlement represented active flag; export for inactive users through separately authenticated session.

## Accepted v1 additions
`PATCH /api/entries/[id]` action `revise` retains the prior snapshot/feedback in history and starts a new draft. `GET /api/admin/deletion-requests` and `PATCH /api/admin/deletion-requests/[id] {action:'fulfill'|'decline'}` are admin-only. Fulfilment erases journal entries, revokes sessions and anonymizes the member profile; backup/application retention is separately governed. Canonical development origin defaults to `http://localhost:3000`; production must set `HMB_ORIGIN`. Restricted staff reads are audited with IDs/scopes only. These additions were communicated to backend and workflow owners and tested together.
